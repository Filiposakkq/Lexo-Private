# Handoff: how work on Lexo is done (read this first in a new chat)

Written so that a new session (or a new person) knows what the project is, what has been decided, how a step is done, and where the checkpoints are.
Keep it current: when a decision or a rule changes, change it here in the same commit.

## 1. What Lexo is
A translation manager for Ren'Py games: edit, proofread, check and track translations (`.rpy` files in `game/tl/<language>/`).
It grows out of the BaDIK Translation Manager (built for the Czech translation of *Being a DIK*; old repo `D:\RenPy Stuff\Being-A-DIK-CZ`, folder `tools/translation-manager`, which keeps working for that translation).
Working name Lexo. Private monorepo `Filiposakkq/lexo-private`, local folder `D:\RenPy Stuff\Lexo`.

Goals, in order: (1) generalise from one game and one language to most Ren'Py games, English UI with Czech as the first language pack;
(2) port to Rust (Tauri: Rust core, web UI); (3) only then the menu with game selection, a new UI, the licence server, Free and Pro versions, an installer.
The code stays private until the owner decides otherwise.

Layout: `core/` (library, later), `free/` (the whole app for now, Python package `lexo`), `pro/` (paid modules, never leaves this repo), `docs/`.
The app is a local HTTP JSON server + pywebview window; the UI is ES modules in `free/lexo/ui/js/NN-name.js` (entry `99-boot.js`).

## 3. Decisions already made (do not re-open without the owner)
- **English text is the key** for every user-visible string. UI: `t("...")`, `tn`, `tx`, `labels`, `N_`. Python: `msg("... {x}", x=...)`, `msgn`, `join`. Czech lives only in `free/lexo/packs/cs/ui.json` (keep it sorted) and in the pack rules. Never wrap a string at module load time (guarded by a test).
- **Language packs are data** (`pack.json`, `rules.json`, `ui.json`), loaded from `lexo/packs/` and `<config>/packs/`; the app must work without any pack.
- **Licensing**: signed Ed25519 key verified offline, check every 30 days with 14 days grace, 2 devices, Pro code only in a private repo and downloaded after the licence, no obfuscation/packers/hardware binding. Dev default = every feature on; `LEXO_TIER=free` simulates Free.
- **Data layout** (docs/DATA-LAYOUT.md): shared small files in `<translation folder>/.lexo/`, local/bulky data in `%APPDATA%\Lexo\projects\<id>\`. Ren'Py 7.4.10 does not exclude nested dot folders from a build, so nothing private or bulky goes into the game folder.
- **unrpyc / unrpa** are only external helpers, native `.rpa` extraction is built in, translation files are generated by the Ren'Py SDK.
- **No menu / new UI / licence server / release before the Rust port.**
- Legacy BaDIK data keeps working (`cs` language, BaDIK layout); a migration reads the old Czech file names, never writes them.

## 4. Safety rules (hard)
1. The game folders on disk are **read-only**. Work on copies or synthetic projects. Never write into a real game or into the BaDIK translation.
2. Never push, open a PR, merge, publish or delete anything outside the working tree **without asking the owner first** (the owner answers "Push + PR"). Describe in the PR what is **not verified**.
3. Never commit secrets, licence keys or private keys. Pro code does not go into `free/` or `core/`.
4. Tests must stay green; do not weaken or delete a test to get green. A flaky test is investigated, not skipped.
5. Writes to user data are atomic and preceded by a backup; the app never deletes a folder it does not own.
6. Do not change files outside `D:\RenPy Stuff\Lexo` unless the owner asked (the old repo is a separate project).

## 5. How a step is done (the loop)
1. **Plan**: read ROADMAP.md and the relevant doc; write the step down (what, why, what "done" means) before coding. If a design choice is the owner's, ask; otherwise choose the conventional option and note it.
2. **Branch** from fresh `main`: `feat/<short-name>` (or `fix/`, `docs/`). One topic per branch.
3. **Implement in small commits.** After each commit run the tests (section 6). Use scripts for mechanical bulk edits and prove them lossless (e.g. joined parts = original, a scanner showing zero left).
4. **Checkpoints** (all must hold before asking to push):
   - Python tests green (`python -m unittest discover -s tests`, in `free/`).
   - UI self-test green (all checks, run in Czech) when anything in `ui/` or the server changed.
   - English UI smoke test (`?lang=en`, all tabs, no Czech except language names) when texts changed.
   - New behaviour has new tests; a bug fix has a test that failed before.
   - Docs updated in the same branch: ROADMAP.md (log + table), plus the specific doc; this file if a rule changed.
   - `git status` clean, no scratch files in the repo, no servers left running.
5. **Ask** the owner: "Push + PR?" Then push, open the PR into `main` with: what changed, how verified, **what is not verified**, and the Claude Code line at the end.
6. CI (`.github/workflows/free.yml`: unit tests + UI self-test in Edge via Playwright) runs on the PR. The self-test is occasionally flaky on slow runners; look at the log, do not just rerun blindly. The owner merges; then `git checkout main && git pull` and start the next step.

## 6. Commands (Windows, from `D:\RenPy Stuff\Lexo\free`)
```
py -m unittest discover -s tests                 # all Python tests (~470)
py tests/ui/serve_selftest.py --no-open          # synthetic project + prints a URL; open it with ?selftest=1&lang=cs
run_ui_selftest.bat                              # same, opens the default browser
py run_lexo.py                                   # the app
```
Stop self-test servers when done (they are `python ... serve_selftest.py` processes). `?lang=en` / `?lang=cs` switches the UI language.
The shell is Git Bash / PowerShell: for multi-line scripts write a file instead of a heredoc with tricky quoting; set `PYTHONIOENCODING=utf-8`.

## 7. Where things are
- Server messages: `free/lexo/messages.py`; wire format `{"$m","p","$n"}` / `{"$j"}`; browser side `ui/js/05-i18n.js` (`fromWire`), `ui/js/10-api.js`.
- Project layout: `layout.py` (reads `_progress_data/project.json`), languages: `lang.py`, features: `features.py`, game tools: `gametools.py`, `rpa.py`.
- Tests that guard conventions: `test_ui_i18n.py`, `test_ui_i18n_load_time.py`, `test_python_messages.py` (allowlist of Czech data constants), `test_messages.py`.
