# Two interfaces side by side: classic and next

The interface is being redesigned (sketches, the list of what must stay: [UI-PARITY.md](UI-PARITY.md)). While that happens **the old interface stays untouched and usable**, and the new one grows beside it, so the two can be compared at any time on the same project.

## What is what

| Name | Where | URL (server) | State |
|---|---|---|---|
| **classic** | `rust/resources/ui-classic/` | `/` | the interface in use; only bug fixes and what parity needs |
| **next** | sources `ui-next-src/` (Vue 3 + Vite) → built into `rust/resources/ui-next/` | `/next/` | the new interface, **under development**: Home, the guide to prepare a game, and the screens of a game (**Overview, Files, Lines, Check, Glossary, Tools, Team, Publishing, Settings**) are built; Only the film layouts, the side-by-side layout, the second window and the focus mode are still the classic ones, linked from the menu of the game |
| archive | git tag `ui-classic-1.0.0` | – | the classic interface exactly as of version 1.0.0 |

The names are the folder names, so nothing is confusable: `ui-classic` is the old one, `ui-next` is the new one. After the switch (below) `ui-next` becomes `ui` and `ui-classic` is gone from the tree (it stays in the tag).

## How to run each

- **Launcher** (`tools/launcher/Spustit-test.cmd`): the box *Nove rozhrani (/next/) misto klasickeho* opens `/next/` instead of `/` (in the browser mode; the window of the application, Tauri, shows the classic one). The box *Klasicke i nove vedle sebe* starts **one** server and opens both interfaces in two tabs: they use the same Core and the same project, so they can be compared at once. (Two separate servers on one project would fight over the project lock, which is why it is one server.)
- **By hand:** start `lexo-server` and open `/` (classic) or `/next/` (new). Both talk to the same Core through `/api` and use the same token, so the same project works in both.
- **Folders:** `LEXO_UI_DIR` replaces the classic folder, `LEXO_UI_NEXT_DIR` the new one (`lexo-server --ui <folder>` too, for the classic one). `/next/` exists only when the folder has an `index.html`; otherwise it is "not found".

## The new interface: sources, build, tests

- **Sources:** `ui-next-src/` (Vue 3, plain JavaScript, Vite). `src/App.vue` is the shell, `src/views/` the screens (Home so far), `src/components/` the parts, `src/i18n.js` a copy of the text module of the classic interface (the same rule: the English text is the key; the same Czech pack `packs/cs/ui.json`), `src/api.js` talks to `/api` with the token of the run. `public/` holds `tokens.css`, `components.css` and the styleguide, which are copied as they are ([DESIGN-SYSTEM.md](DESIGN-SYSTEM.md)).
- **Build:** `cd ui-next-src && npm install && npm run build` (Node is needed only for this). It writes `rust/resources/ui-next/` (git ignores it, only its README stays); the launcher has a box *Nejdriv sestavit nove rozhrani*. The built files are plain static files, so the application never needs Node or Vue at run time.
- **Develop:** `npm run dev` serves the sources at `http://localhost:5173/next/` and forwards `/api` to a running server (`VITE_API=http://127.0.0.1:<port>`).
- **Tests:** `npm test` (Vitest + Vue Test Utils); the workflow *New interface* runs the tests and the build. The Czech texts of the new interface are checked by the same test as the classic one (`test_ui_i18n`: every text has a Czech text, nothing is stale).
- **Prepare a game:** the guide (`src/views/Prepare.vue`): choose the game folder and the language, the application looks at the game (engine of its own, scripts, archives), asks for unrpyc only if needed, then runs the steps as a job and shows them as they go; at the end the translation is on Home and can be opened. The steps and their rules are in [GAME-TOOLS.md](../technical/GAME-TOOLS.md).
- **Library of games:** Home reads `library/list` (`library/add`, `library/remove`, `library/pin`): a local file `library.json` in the settings of the application, never in a project; a project that is opened is put on Home by itself. Opening a game calls `project/set` and goes to its **Overview** in the new interface.
- **Screens of a game** (`src/views/Overview.vue`, `Files.vue`, `Lines.vue`, shared state in `src/project.js`): a menu on the left (Overview, Files, Lines, then links to the classic screens that are not built yet). Overview: where you are, one click to continue, the four numbers, progress by group, files by state, recent activity. Files: every column of the classic table (file, assignment, translation, proofreading, left to translate, left to proofread, state, check), search and filters, sorting, the assignment of a file, *mark the whole file as proofread*, the detail with *Show lines*, *Only untranslated*, *Continue proofreading*, *Open in the editor*, *Copy the path*. Lines (the list and the line scroll by themselves and the page stays, like in the classic one; what every line needs is fetched once and kept): **all the columns** (file, line, script, type, state, proofreading, code, name, original, translation, check), the filters and counts of the classic screen, loading more, and the line on the right (approve, proofread, to fix with a note, the editor, save with Ctrl+Enter and the live check, next untranslated / unchecked / too long). The line detail also has the tag snippets, the missing variables, the glossary terms, the machine suggestion, the jumps (scenes, next untranslated / unchecked / too long) and the tabs Check (ignore, fix), Proofreading, Menu, Scene, Memory, History, Team (notes) and Script; *Approve all identical*. The tools open, from their own **Tools** screen (the lines keep only *Translate with a machine…* for the lines you picked, and the scene button), as dialogs with a preview, find and replace, approve by rule, texts the generator missed, carry over, fill from similar, fixes, machine translation, style check, spelling and the release builder (`src/components/*Dialog.vue`; the Pro ones ask `requireFeature` first, `src/pro.js`). **Groups** (a dialog from Overview and Files) and **Team** (its own screen: you, members, roles, offering the lead, news, git buttons, statistics, ending the team; in Files the column *Assigned to* and the filter by person) are built too. The **Scene** tab draws the picture of the game window, which collapses like the scene around the line, the memory and the history, the choice being remembered (the background and the pictures shown over it, the game font and the text box of the game, the text following the editor; `src/gamewindow.js`, `src/components/GamePreview.vue`) and the lines around the open one as a table or as bubbles, with *Translate the scene with a machine…*; a line of dialogue that belongs to a menu gets the **Menu** tab as well as a choice does. **Check** (`src/views/Check.vue`) has the four views of the classic screen: Findings (one line with all its findings, the filters, the counts, *Fix*, *Ignore…* with a note, *Ignore all*, *Show* and *Editor*, undo of the last fix), Different translations (the same original translated differently, *Unify…* with the lines you tick, *Leave as it is*), Ignored findings (with the state of each and *Stop ignoring*) and the game lint; the line detail uses the same Ignore and Fix dialogs. Not yet in the new screens (they stay in the classic interface and in the parity list): the film layouts (quick translating and proofreading, the results bar), the side-by-side layout and the second window, the focus mode and the shortcuts dialog. **Publishing** (`src/views/Publish.vue`): generate and check the data for the website, then the publishing preview with the git commands and the confirmation. **Settings** (`src/views/Settings.vue`): language, project folder, skipped files, editor, goals, the check, machine translation, backups (create, restore, delete) and lint, the website; **Shortcuts** (`src/keys.js`: the list of actions with their keys, the keys you changed kept in this browser, the handlers that the open screen registers; the help `?`, the command palette `Ctrl+K`, the panel in Settings that captures a key and asks before it takes one from another action) and **Licence** (`LicencePanel.vue`: the state, entering a key, the regular check, your computers with rename and remove, a lost key) are built too. **Glossary** (`src/views/Glossary.vue`): the speakers and the terms with the filters (all, without a name, speaker, terms), search (whole word), the speaker display, names and notes saved when you leave the field, add and delete, *Occurrences* of a term, the *Profile…* of a character (Pro) and the import from `characters.rpy` (`OccurrencesDialog`, `ProfileDialog`, `GlossaryImport`).

## Rules while both exist

1. **The classic interface is not restyled or rebuilt.** Only bug fixes, and changes that a Pro feature or the contract needs (a new feature appears in both until the switch).
2. **The new interface does through `/api` exactly what the classic one does.** Every action of the classic one is a line of [UI-PARITY.md](UI-PARITY.md), with the place where the new interface has it. Nothing is removed from the classic one before its line is filled.
3. **Links inside the new interface are absolute** (`/next/assets/x.js`), and `__TOKEN__` in its `index.html` is replaced by the token of the run, like in the classic one.
4. **The installer ships the classic interface only** (`tauri.conf.json` bundles `ui-classic` as `ui`). The new interface is added to the installer when it is ready to be tried by users, as a choice, and replaces the classic one at the switch.
5. The tests (the UI self-test, the contract test of the routes, the texts) run against the classic interface until the new one has its own self-test; the new interface gets the same checks before the switch.

## The switch (when the new interface is done)

1. Every line of the parity list is filled and ticked; the new interface passes the same self-test as the classic one.
2. `rust/resources/ui-next` is renamed to `rust/resources/ui` (and its build output is what is shipped); `ui-classic` is deleted from the tree. The tag `ui-classic-1.0.0` keeps it.
3. The paths in `tauri.conf.json`, the workflows, `lexo-server`, the Python tests and the launcher are changed back to `ui` (they were changed from `ui` to `ui-classic` when this layout was made, and the new folder was added).

## About the framework

The new interface may be written in a framework (Vue was discussed). It does not matter for this layout: whatever is built is copied into `ui-next/` as plain files (`index.html`, `assets/…`), and the sources go to their own folder (planned: `ui-next-src/`), so the application and the installer never depend on a build tool at run time.
